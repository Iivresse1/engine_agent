# 双运行时：TS 前端 + Python 后端

终端外观与图执行分成两个进程级运行时：**前端**（TypeScript + React 19 + Ink）只负责观感、按键与渲染，**后端**（Python，现有全部模块）只负责 REPL 宿主逻辑、主工作流图、旁路、账单与磁盘。两者只经**协议消息**对话，前端不直接读写项目状态与 checkpointer。

选它而非继续单进程 Python REPL，是因为外观要做到 Claude Code 那一档（信息层次、面板折叠、按键提示、中文列宽按东亚字符宽度算）在纯 Python 终端栈里代价过高，而 Ink 生态已经把这块做完了；同时把渲染从图与状态中切出去，观感迭代就不会再牵动断点协议与状态契约这两条最难对的线。代价是多一个运行时、多一条协议接缝——因此接缝预算钉死为**只新增一条**（前端↔后端），后端↔图的主接缝保持原样。

许可红线：参考仓 `claude-code-best/claude-code` 无 License（全权保留），只学架构模式、绝不复制代码；前端依赖必须是 MIT/Apache 等宽松许可（Ink 用 npm 正版）。tkinter 仍只用于首启配置窗口——"Windows 观感"就那一处。

过渡态：前端未接线期间后端保持可直接裸终端运行（现状即此形态）；无显示环境一律退终端问卷。
