# implement-spec 派工手册

派工 implementer 子代理前必读。三个钉子：**零决策点**派工单、**切片**预算、**残留**优先。

## 零决策点派工单

子代理死于上下文耗尽的根因（本仓 02/03/05/08 首派实测，4 死 0 提交）：
派工单留了决策点，子代理用宝贵上下文做设计推演。派工单把设计做完，
子代理只剩执行——判断标准：**单子里每处"如何"都有唯一答案，子代理
读完零悬空**。

派工单五要素（全部必须，缺一即补齐再派）：

1. **验收测试清单**：文件+函数名，逐条列出。子代理以此判断完成。
2. **已定决策**：引台账 Q#（`.scratch/<feature>/decisions.md`），只给
   结论不给推理。推理在派工前由 Lead 完成。
3. **文件级伪代码**：每个文件（新建/修改）给到函数级伪代码，输入输出
   类型写明。节点工厂签名、state 键名逐字钉死。
4. **切片表**：见下节。
5. **禁改清单**：共享热点文件（`nodes.py`、`graph.py`）本轮哪些区段
   不许碰；工具/协议模块默认禁改，要改先回报。

## 切片预算

每片子代理一次汇报往返。预算规则：

- ≤5 片。第 5 片（末片）**只做合并收口**（merge、跑全量测试、勾票），
  零新代码零新测试。
- 每片以可验证状态收尾：该片的验收测试转绿，全量测试无回归。
- 切片边界落在文件边界或函数边界上，跨文件半成品留在切片内完成。

## 子代理死亡处置：残留优先

子代理死讯到手（超时/上下文耗尽/失联），第一动作是查 **残留**，直接
重派会覆盖它（10/11 票实测：工作完整但死于汇报前，重派=白干一遍）：

1. 查该子代理 worktree 的提交：`git -C <worktree> log --oneline`，
   对照切片表判断死在第几片。
2. 跑它留下的测试看红绿：全绿且切片表走完 → 直接采纳收口；
   有红 → 修复后收口；断档 → 从断点片重派（派工单复用，切片表
   从断点重编号）。
3. 采纳前确认残留无越界：`git -C <worktree> diff --stat` 对照禁改清单。
4. worktree 用完即清（`git worktree remove`），残留文件先收编再清。

## Windows 工具坑（一行）

`git apply` 吃 `Out-File` 写的 BOM 直接失败——跨分支取文件用
`git checkout <branch> -- <path>`，别走 patch 管道。
